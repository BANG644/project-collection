## 项目全景

WeFlow 是 2026 年初涌现的微信聊天记录本地工具，核心主张是「**完全本地**的微信实时聊天记录查看、分析与导出」。其差异化在于「实时」+「年度报告」组合：不仅能把加密聊天库解密导出，还能基于聊天数据生成独一无二的数据可视化与年度报告。

**关键事实**：当前 GitHub 仓库根目录仅剩 `README.md` 与 `app.jpg` 两张文件，**源码已被 DMCA 下架剥离**，因此本报告无法做源码级解读，仅能基于 README 声明、预览图与同类技术路线做架构还原与生态研判。

## 核心架构（基于同类路线还原）

WeFlow 与同品类（WeChatMsg / Memotrace）共享同一套技术范式，区别在工程化包装（实时 + 年度报告）：

```
微信进程内存 → 提取 SQLCipher 密钥 → 解密本地 SQLite
        │
        ├─► 实时查看层（聊天流渲染）
        ├─► 分析层（词频 / 活跃时段 / 关系网络）
        └─► 年度报告生成（数据可视化：日历热力 / 词云 / 时间轴）
```

- **解密层**：与 WeChatMsg 一致 —— 从微信进程内存提取密钥，SQLCipher 打开 `Msg.db`。
- **实时层**：监听/轮询解密后的库，near-real-time 渲染聊天流（区别于事后批量导出）。
- **年度报告层**：对消息做统计分析（发送量、时段、Top 联系人、热词），用可视化库生成年度报告页。

## 应用场景与启发

- **个人数据可视化 / 年度报告**：把一年聊天变成可回看的「数字日记」，是情感化数据的强需求场景。
- **数据主权叙事**：WeFlow 的走红与下架，集中暴露了「平台锁定用户数据」与「用户对自己本地数据的权利」之间的张力。
- **🔧 给同类需求的启发**：
  - 「实时查看 + 年度可视化」比「一次性导出」更有留存价值与传播性（年度报告天然适合朋友圈分享，带来裂变增长）。
  - **合规边界是生死线**：同类工具普遍游走在 DMCA / 用户协议边缘；WeFlow 案例证明「技术可行 ≠ 可长期公开运营」，架构上应预留「无源码分发 / 本地私有部署」的退路。
  - 面对下架，**把 README 变成社区宣言**是低成本维系热度的聪明做法。

## 核心研判

- **价值**：作为「数据主权 vs 平台锁死」的标志性案例 + 实时+年度报告的产品形态创新，WeFlow 在「产品叙事」与「社区运营」上远超绝大多数技术同行。其 README 本身就是一篇值得研究的增长 / 危机公关教材。
- **风险**：① 源码已被 DMCA 下架，技术资产归零；② 法律合规是结构性风险，无法靠工程解决；③ 强依赖微信私有格式，停更即技术失效。
- **趋势**：微信数据导出需求长期存在且高频，但「公开仓库 + 完整源码」模式不可持续；更稳的形态是「本地私有部署 / 闭源分发 / 云端合规方案（如 WechatOnCloud）」。
- **给开发者启发**：做敏感品类，**产品叙事与社群运营能力**往往比代码更决定生死；架构上从第一天就设计「源码不在公开仓库也能分发」的通道。

## 项目全景

WeChatMsg（又名「留痕」）由 SiYuan（LC044）于 2022 年创建，解决一个朴素但长期被忽视的痛点：**你存在自己电脑上的微信聊天记录，实际上被加密锁死，微信官方不提供任何导出能力**。项目以「我的数据我做主」为口号，提供一套本地化的解密 + 解析 + 导出流水线。

技术栈以 **C# / .NET (WPF)** 桌面客户端为主，辅以 Python 脚本（GitHub topics 含 `pyqt` / `wechat` / `llms`）。注意：GitHub languages API 对本体返回空（仓库体积主要由发布二进制/资源占主导），但社区共识其主程序为 WPF。

当前版本已停止维护，但社区涌现出 Memotrace（同名社区维护分支）延续生命。本项目作为「品类定义者」仍具极高参考价值。

## 核心架构

整体是一条「**定位微信数据目录 → 提取解密密钥 → SQLCipher 解密 → 解析消息表 → 多格式渲染**」的本地流水线：

```
微信进程 (WeChat.exe)
   └─ 内存中的 DB 密钥 (SQLCipher key)
         │  (特征码扫描 / 内存读取)
         ▼
WeChatMsg 解密模块
   └─ 打开 Msg.db / MicroMsg.db (SQLite+SQLCipher)
         │
         ▼
解析层 (联系人 / 消息 / 表情 / 图片 / 语音 / 文件)
         │
         ▼
渲染层 ──► HTML(带图) / Word / Excel / CSV
         └─► AnnualReport 年度报告可视化
```

四个关键环节：
1. **密钥提取**：微信 PC 版数据库使用 SQLCipher 加密，密钥在微信进程运行时存在于内存中。工具通过进程特征码定位并读取该密钥（需微信处于登录状态）。
2. **SQLCipher 解密**：用提取到的密钥打开加密 SQLite，得到明文表。
3. **表结构解析**：`MSG` 表（消息）、`Contact` 表（联系人）等，处理 emoji/图片/语音/文件/引用/合并转发等复杂消息类型。
4. **多格式导出**：HTML 保留图文语境；Word/Excel 适合归档与检索。

## 应用场景与启发

- **个人数据主权**：你的聊天记录、工作对接、家庭照片，理应属于你自己。本项目是「本地优先 + 用户 owns 数据」范式的典型落地。
- **情感留存 / 年度报告**：把冷冰冰的数据库变成可回看的年度故事，启发了后续 WeFlow、AnnualReport 等同类叙事。
- **法律取证 / 合规归档**：企业微信、工作对接的记录导出是刚需场景。
- **🔧 给同类需求的架构启发**：
  - 「**解密密钥在进程内存中**」是几乎所有 PC 客户端加密数据提取的通用突破口 —— 不止微信，凡是「本地加密 + 运行时解密」的桌面程序都可套用「内存密钥提取 + 解密」两步走。
  - 多格式导出（HTML 保语境 > Word 归档 > Excel 检索）是这类工具体验分水岭。
  - **但必须持续适配客户端版本**：微信每次大版本都可能改密钥派生/表结构，停更即失效 —— 这是此类工具的宿命式维护成本。

## 核心研判

- **价值**：作为品类定义者，其技术路线（内存密钥提取 + SQLCipher 解密 + 多格式渲染）已成事实标准，后续所有同类工具都建立在其肩膀上。对「本地优先隐私数据处理」研究而言是不可绕过的样本。
- **风险**：① 停更导致对新版微信失效；② 法律合规高压（同类 WeFlow 已遭 DMCA 下架）；③ 强依赖单一闭源客户端（微信）的私有格式，逆向维护成本不可持续。
- **趋势**：个人数据主权意识觉醒，但「在合规边界内做本地导出」会越来越难；未来更可行的方向是「用户主动备份 + 端到端加密云同步」（如 WechatOnCloud 路线）或「官方开放导出 API」。
- **给开发者启发**：做此类工具，**社区分支化 + 持续版本跟进**比「单打独斗」更可持续；架构上「解密层与渲染层解耦」能让适配成本集中在解密层。
